# Design decisions

Decisions made after the proposal, where the proposal left room. Code must follow these.

| # | Date | Area | Decision | Why |
|---|---|---|---|---|
| D1 | 2026-11-12 | Score (§7.5) | A finding the **creator rejects** still deducts. Only reviewer/owner **dismiss or waive**, or a new version where the issue is gone, removes the deduction. | Creators can't raise their own score or bypass the approval gate (§8.1). The rejection reason is shown to the reviewer. |
| D2 | 2026-11-12 | Confidential Guard | Match registered internal terms as **whole words**, case-insensitive, with any run of spaces/hyphens/underscores/line breaks between words. "Project Atlas" catches `PROJECT-ATLAS`, `project  atlas`; does not catch `Atlassian`. | Avoid false Criticals that block approval. Owners should register specific names ("Project Atlas"), not generic words ("Atlas"). |
| D3 | 2026-11-12 | Evidence validator (§7.3) | If the AI's quote exists **anywhere** verbatim in the content, keep the finding and **correct the offsets** to the occurrence nearest the stated offset. Discard only if the quote does not exist at all. | Models miscount characters; the verbatim quote is the real evidence. |
| D4 | 2026-11-12 | Contrast on images | Extract dominant colours from the image and check the lowest-contrast text-like pair (**medium** confidence). If the creator enters text + background colours on the upload form, check those exactly (**high** confidence). | Keeps contrast a measurable code check (§9.1) and keeps the demo's 3.1:1 banner finding. |
| D5 | 2026-11-12 | Wording rule pack | Hype, absolute-claim, vague-source and AI-phrasing checks come from MIT rule sets (vale-ai-tells, marketing-machine), generated into `src/lib/rules/packs/marketing-en.json` by `scripts/build-rulepack.py`. Every pack finding is **medium** confidence with no auto-fix; owners can switch rules off (`disabledPackRules`). `PACK-AI-VOCAB` is **info** (no score impact): on a human-written 62-page PDF it fired 11 times on ordinary words ("significant", "crucial"). | A phrase match is a signal, not proof (§7.4). Medium keeps the score impact small (minor = 1.8) so a reviewer dismissal, not the creator, decides. |
| D6 | 2026-11-12 | System rule codes | Findings not tied to an org clause/fact/term use fixed codes: `WCAG-1.4.3`, `WCAG-1.1.1`, `READABILITY`, `BRAND-PALETTE`, `BRAND-FONTS`, `PACK-*`. The `findings` table needs a `rule_code text` column to store them (next migration, with the audit API). | `brand_assets` has no code column and WCAG/pack rules are not org data, but every finding must still name its source (§7.3). |
| D7 | 2026-11-12 | Web-page fetch | DNS is resolved and every address checked before each request and redirect (max 3); http/https on ports 80/443 only; 2 MB / 10 s limits; HTML only. Shortcut: no protection against DNS rebinding between lookup and connect. | Covers the SSRF cases in PLAN.md §6; full rebinding protection needs a custom dispatcher, out of MVP scope. |
| D8 | 2026-11-12 | Image colours | Dominant colours are computed with `sharp` (96 px, 8 levels per channel, mean colour per bucket, pixel share) instead of node-vibrant. | Palette and contrast checks need each colour's share of the image; the result is deterministic, so the same image always gives the same findings. |
| D9 | 2026-11-12 | DB tests | Migrations, RLS and `save_audit()` are tested on **PGlite** (in-process Postgres) with a small Supabase shim (`tests/db/harness.ts`). The hand-run SQL suites (19 RLS + 7 gate) now run in CI. | No Docker or Supabase project in CI; the shim mirrors Supabase's roles, grants and `auth.uid()`. Full Supabase (Auth, REST, Storage) is still checked with `supabase start`. |
| D10 | 2026-11-12 | `/api/audit` | The item and version are created with the **user's** client (RLS decides who may submit); knowledge is read and the run saved with the **service** client through `save_audit()`, one transaction. AI skipped/failed is stored as `mode = 'rule_only'`. `today` is the date in India (Asia/Kolkata). Shortcuts: uploaded files are not yet kept in Storage (`file_path` empty), and there is no per-org daily AI cap yet (§11.5). | Creators must not be able to write runs or findings themselves, and the Confidential Guard needs internal terms the creator can't read. |
